## 2. Phase 0：更换系统镜像（用户控制台操作，趁空机零成本）

**为什么换 24.04**：本地 WSL 是 Ubuntu 24.04（Boost 1.83 / glibc 2.39），后端已在 WSL 适配完成（`linux/` 目录：CMakeLists + vcpkg manifest，protobuf 6.33.4 硬校验）。服务器换 24.04 后 glibc/Boost 完全对齐，**WSL 编好的二进制直接 rsync 上云**，绕开"2G 内存服务器编译 gRPC/protobuf"的坑。

操作：ECS 控制台 → 实例 → 停止 → 更换操作系统 → Ubuntu 24.04 64位 → 重置 root 密码。

## 3. Phase 1：安全加固（换完镜像立刻做）

### 3.1 SSH 密钥登录（本机专用密钥已生成）
- 私钥：`~/.ssh/<你的SSH私钥文件名>`，公钥：`~/.ssh/<你的SSH公钥文件名>.pub`
- 上装公钥（用户输一次密码）：
  ```powershell
  type $env:USERPROFILE\.ssh\<你的SSH公钥文件名>.pub | ssh root@<服务器公网IP> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
  ```
- 服务端 SSH 登录：`PasswordAuthentication yes`、`PermitRootLogin yes`（**密钥 + 密码共存**，密码登录可用），改完 `systemctl restart ssh` 生效。⚠️ 密码开启后，建议把安全组 22 端口的源从 `0.0.0.0/0` 收窄到本机出口 IP，避免全网暴力破解。

### 3.2 安全组规则（控制台 → 安全组 → 配置规则）
放行：`22/TCP`、`8080/TCP`、`8990/TCP`、`8991/TCP`（源 0.0.0.0/0；22 可收紧到常用出口 IP）。
**明确不开**：3308 / 6380 / 50051 / 50052 / 50055 / 50056。

### 3.3 系统基线
`apt update && apt upgrade -y`；创建 2G swap（`fallocate 2G /swapfile`...，写入 fstab）；可选 fail2ban。

## 4. Phase 2：数据面（MySQL + Redis）

```bash
apt install -y mysql-server redis-server libmysqlclient24
```
- 保持项目端口：MySQL `3308`、Redis `6380`（少改 config）
- **必须** `bind-address = 127.0.0.1`（MySQL）/ `bind 127.0.0.1`（Redis）+ `requirepass`
- 2G 内存 MySQL 调参：`innodb_buffer_pool_size=128M`、`performance_schema=OFF`、`max_connections=100`
- 导入数据：`mysql -P3308 -uroot -p < sql/hcat_current.sql`（建库 + 测试用户 uid 2/3/5/6/7/8）

## 5. Phase 3：后端产物上云

1. WSL 内 `bash linux/build_wsl.sh` 出 release 二进制（vcpkg 静态依赖已打入，含 protobuf 6.33.4）
2. `rsync -avz` 二进制 + proto 无需（已编译）+ `linux/start_services.sh` 到服务器 `/opt/hchat/`
3. 服务器 apt 装运行时库：`libmysqlclient`（Connector/C++ .so 依赖）、`libboost-system/filesystem 1.83`（apt 24.04 版本即 1.83，天然对齐）
4. **config.ini 三处公网 IP 改动**：
   - `Client/config.ini` → `[GateServer] host=<服务器公网IP>`（本地客户端侧）
   - `StatusServer/config.ini` → `[chatserver1] Host=<服务器公网IP>`、`[chatserver2] Host=<服务器公网IP>`（**下发给客户端的连接地址**，改错则远程客户端拿到 127.0.0.1 连不上聊天服务器）
   - MySQL/Redis 的 Host 保持 `127.0.0.1`
5. VarifyServer：apt/NodeSource 装 Node 20+，`npm install`（gRPC for Node），监听 50051 仅本地

## 6. Phase 4：systemd 常驻

五个 unit（模板）：
```ini
# /etc/systemd/system/hchat@.service （模板化，%i = gate/status/chat1/chat2/varify）
[Unit]
Description=HChat backend %i
After=network-online.target mysql.service redis-server.service
[Service]
WorkingDirectory=/opt/hchat
ExecStart=/opt/hchat/%i   # 各服务二进制 + 各自 config.ini
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
```
启动顺序：mysql/redis → varify → status → gate → chat1/chat2；`systemctl enable --now hchat@*`。

## 7. Phase 5：联调与运维

- 联调清单：注册/登录（Varify 验证码）→ 换 token → 单聊/群聊（两台 ChatServer 跨机共享 Redis）→ 图片上传 → 断线重连
- mysqldump 每日 cron 备份到 `/opt/hchat/backup/`（不入 git）
- spdlog 日志轮转已有；观察 `journalctl -u hchat@*`
- **3 Mbps 注意**：图片上传 300MB 需 ~13 分钟，公网联调可临时把 `[Upload] MaxBytes` 调小（客户端与服务端两处一致）
- 计费：按量付费，长期不用选"节省模式停机"或释放

## 8. 风险备忘

1. **config.ini 里数据库/Redis 密码已随仓库提交**——上云后建议换一套生产密码，且云上 config 不回传仓库
2. protobuf 6.33.4 是硬校验（生成的 pb.cc 会核对版本），**不要**用 apt 的 protobuf 3.x 替代
3. 若不换 24.04 而保持 22.04：glibc 2.35 跑不了 WSL 产物，只能服务器现编（挂 4G swap、-j1）或上 Docker
4. 安全组规则改动即时生效，MySQL/Redis 暴露公网是最高危事故，每次改动后复查

- **验证**：本地 `curl http://<服务器公网IP>:8080/health` → HTTP 200、0.08s、`{mysql:ok,redis:ok,status:ok}`。

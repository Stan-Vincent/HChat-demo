### 编译错误：connect 写进了 TcpMgr 构造函数（已修）
现象：`tcpmgr.cpp:81` 报 `no matching function for call to TcpMgr::connect(...)` +
`no type named 'type' in 'struct std::enable_if<false, QMetaObject::Connection>'` +
`no type named 'type' in 'struct std::_Less<...>'`。
原因：把 `connect(TcpMgr::GetInstance().get(), &TcpMgr::sig_login_failed, this, &LoginDialog::slot_login_failed)`
写进了 `TcpMgr::TcpMgr()` 里。`tcpmgr.cpp` 虽然 include 了 logindialog.h（所以类型认识），
但**构造函数里的 `this` 是 `TcpMgr*` 不是 `LoginDialog*`**；匹配失败后编译器退化成
`QMetaObject::Connection*`，于是报出那串 enable_if 错误。

**原则：`connect` 要写在"接收方"的构造函数里**，因为 `this` 要充当 connection 的 context 对象
（决定连接何时随接收方销毁而断开）。被监听方不该知道谁在监听自己。

### 排查「登录返回 1011」—— 根因是数据库表结构不全（已修）
现象：客户端登录 → ChatServer 日志
```
Succeed to execute command [ GET utoken_3 ]      ← token 校验通过
[ GET  ubaseinfo_3 ] failed                      ← Redis 无缓存，回落 MySQL
SQLException: MySQLPreparedResultSet::getString: invalid 'columnIndex'
```
→ `LoginHandler` 置 `rtvalue["error"] = UidInvalid(1011)` → 客户端 "Login Failed, err is 1011"。

**根因**：`MysqlDao::GetUser(uid)` 里 `SELECT * FROM user WHERE uid = ?` 读了
`pwd/email/name/nick/desc/sex/icon` 七列，而本项目 `xxxl.user` 表只有
`id/uid/name/email/pwd/nick/icon` —— **`desc` 和 `sex` 两列不存在**，
JDBC 按列名找不到列就抛 `invalid 'columnIndex'`（不是"查不到行"，是"列不存在"）。

**已执行的迁移**（纯新增，未动原有数据）：
```sql
ALTER TABLE `user`
  ADD COLUMN `desc` varchar(255) DEFAULT NULL AFTER `nick`,
  ADD COLUMN `sex` int NOT NULL DEFAULT 0 AFTER `desc`;
```
并补建 6 张业务表（原先 `xxxl` 只有 `user` / `user_id`）：
`friend_apply`（含 `UNIQUE(from_uid,to_uid)` 供 `ON DUPLICATE KEY UPDATE`）、
`friend`（PK 供 `INSERT IGNORE`）、`chat_thread`、`private_chat`、`chat_message`、
`group_chat_member`（列名是 `thread_id`+`user_id`，因为 `GetUserThreads` 的
UNION 分支写的是 `SELECT thread_id ... FROM group_chat_member WHERE user_id = ?`）。

字段全部从 `ChatServer/MysqlDao.cpp` 的 SQL 反推。校验：
`SELECT ... FROM user WHERE uid=3` 现在正常返回，`desc=NULL, sex=0`。

**顺带发现的日志线索（未修）**：
1. `heartbeat expired`：`CServer` 定时器 60s 一跑，`IsHeartbeatExpired` 阈值只有 **20s**，
   而客户端 `TcpMgr` **还没实现发心跳** → 登录成功后 20~80s 内必被踢。
2. `[ GET usession_0 ] failed` ×2：登录失败时 `session->SetUserId(uid)` 没执行，
   `DealExceptionSession` 拿 `_user_uid=0` 去查 `usession_0`。无害但说明清理路径没走到。
3. 客户端用 `QJsonDocument::Indented` 发包（带换行和缩进，70 字节里约 20 字节是空白），
   应该用 `Compact`。
4. `ubaseinfo_<uid>` 这个 Redis 缓存**从来没有被任何服务写入过**（GateServer 注册时没写），
   所以每次登录都必然回落 MySQL；`GetBaseInfo` 读成功后会回写，第二次登录才命中。

## 双击 Hchat.exe 报「无法找到入口点 __emutls_v._ZSt11__once_call」（已修）
现象：编译链接全过（exe 75.9 MB），但**双击 exe** 弹窗报缺少入口点；从 Qt Creator 里点运行却正常。

**根因**：`bin/` 目录里一个运行时 DLL 都没有，exe 依赖
`libstdc++-6.dll / libgcc_s_seh-1.dll / libwinpthread-1.dll`，Windows 只能去 PATH 找。
本机 PATH 里有**两套 MinGW**：
- `D:\QT6\Tools\mingw1120_64\bin\libstdc++-6.dll` ← 有该符号 ✅（Qt Creator kit 用的就是它）
- `C:\msys64\mingw64\bin\libstdc++-6.dll` ← **没有该符号** ❌（MSYS2 GCC 16.1）

Qt Creator 运行时会把 kit 的 MinGW 插到 PATH 最前面，所以 IDE 里没事；
**双击 exe 用的是系统 PATH，捞到了 MSYS2 那份 → 入口点找不到**。

**修复**：把运行时 DLL 放到 exe 同级目录（Windows DLL 搜索顺序里 exe 目录优先级最高）：
- MinGW 运行时 3 个：`D:\QT6\Tools\mingw1120_64\bin\{libstdc++-6,libgcc_s_seh-1,libwinpthread-1}.dll`
- Qt6 运行时 4 个：`D:\QT6\6.5.3\mingw_64\bin\{Qt6Core,Qt6Gui,Qt6Widgets,Qt6Network}.dll`
（bin 目录因此从 2 个文件变成 99 MB）

并把这步**固化进 `Hchat.pro` 的 `QMAKE_POST_LINK`**（和已有的 config.ini 拷贝同一个 win32 块），
以后编译自动就位。注意 `.pro` 里反斜杠要写 `\\`（qmake 转义成一个），
已验证生成的 Makefile 里是 `copy /Y "D:\QT6\Tools\mingw1120_64\bin\libstdc++-6.dll" "..."`。

顺手修了 `Hchat.pro` 里 `RESOURCES += rc.qrc \ rc.qrc` **重复写了两遍**。

验证：`bin/Hchat.exe` 后台启动 4 秒存活 → 启动正常。

**⚠️ 记住这个坑**：只要改动过用哪套 MinGW 编译，就必须同步 exe 同级的运行时 DLL，
否则会出现"IDE 里能跑、双击就崩"。

### 紧接着的第二个坑：报 "no Qt platform plugin could be initialized"

## GateServer 从 x64\Debug 直接运行闪退（已修）
现象：在 `GateServer\x64\Debug` 里双击/直接运行 `GateServer.exe` 闪退；从 VS 里启动正常。

## 部署第二台 ChatServer（复制目录的方式）
用户把 `ChatServer/` 整目录复制成 `ChatServer2/`。**思路正确**（这套代码本就是多实例设计的），
但复制后必须改配置，否则两台打架。已把 `ChatServer2/config.ini` 改对：

| 项 | 复制后（错） | 已改为 |
|---|---|---|
| `[SelfServer] Name` | chatserver1 | **chatserver2** |
| `[SelfServer] Port` | 8990 | **8991**（要等于 StatusServer 的 `[chatserver2] Port`） |
| `[SelfServer] RPCPort` | 50055 | **50056** |
| `[PeerServer] Servers` | chatserver2 | **chatserver1** |
| `[chatserverN]` 段 | 指向 chatserver2:50056 | **chatserver1:50055** |

`Name` 写错最隐蔽：Redis `logincount` 是 **hash，field 就是服务器名**，两台都叫 chatserver1
会互相覆盖对方的在线数（ChatServer 的 60s 定时器 `HSet(LOGIN_COUNT, server_name, count)`）。

**当前四份配置的一致性（已交叉核对通过）**：
```
ChatServer    chatserver1  TCP 8990  RPC 50055   peer -> chatserver2 127.0.0.1:50056
ChatServer2   chatserver2  TCP 8991  RPC 50056   peer -> chatserver1 127.0.0.1:50055
StatusServer  告诉客户端: chatserver1 127.0.0.1:8990 / chatserver2 127.0.0.1:8991
```
两台**共用同一个 Redis 是设计如此**：`lock_<uid>`（分布式锁）、`uip_<uid>`（用户在哪台机）、
`usession_<uid>` 都要跨服共享，否则跨服踢人失效；只有 `logincount` 是按服务器名分 field。

⚠️ **但 StatusServer 的负载均衡还是关的**：`getChatServer()` 里整段判断被注释，
固定 `return _servers.begin()->second` → 永远返回 chatserver1，客户端永远连 1 号。
要真正分流需恢复那段读 Redis `logincount` hash、选 `con_count` 最小的代码
（数据侧已经就绪：ChatServer 定时器每 60s 上报一次）。

⚠️ 工程标识未改：`ChatServer2/` 里的工程文件仍叫 `ChatServer.vcxproj` / `ChatServer.sln`，
`ProjectGuid` 与 1 号完全相同（`{a0ce642d-...}`）。各自独立构建不受影响，
但**一旦放进同一个解决方案就会 GUID 冲突**。另外已删掉复制带来的 57 MB 旧构建产物
（`ChatServer2/ChatServer/`，会造成时间戳倒挂）。

## 新建 Start/ 目录：一键启动 / 停止全部服务
用户想写个"启动所有服务器"的程序。我建议**不要用 C++ 写**（要的东西是 CreateProcess/进程管理/
端口检查，和 Boost.Asio、连接池、分布式协调这些学习目标无关），改用两个批处理。

`Start/start.bat`（GBK 编码，cmd 代码页 936）：
- `pushd "%~dp0.."` 取规范化的工程根路径
- **关键坑**：`start "标题" /D "目录" 相对路径.exe` 是**无效的** —— start 会在切换工作目录
  **之前**解析程序路径，相对路径按脚本当前 cwd 找 → 找不到 exe，静默不启动。
  必须写**绝对路径** + `/D` 指定工作目录。（VarifyServer 用 `cmd /k` 反而能成功，因为 cmd 会真切 cwd。）
- 各 exe 绝对路径用变量存：`GATE_EXE` / `STATUS_EXE` / `CHAT_EXE` / `CHAT2_EXE` / `CLIENT_EXE`
- 用 `ping -n 2 127.0.0.1 >nul` 做延时，**不要用 `timeout`**（输入被重定向时 timeout 会报错）
- 启动前检查 3308/6380 是否在监听
- 支持参数：`backend`（不起客户端）、`chat2`、`gate`/`status`/`chat`/`varify`/`client`（单起）

`Start/stop.bat`：按监听端口反查 PID 结束进程。
**踩坑**：先写成 cmd 内层 `for %%P in (...) do ( for /f "tokens=5" %%A in ('netstat -ano ^| findstr ...'))`，
**嵌套 for /f 里的管道会静默失灵** —— 第一次跑没杀掉任何进程却输出"全部关闭完毕"，第二次才杀掉。
另外 `find /I` 在装了 Git Bash 的机器上会解析成 **GNU findutils**（不认 `/I`，报 `find: '/I': No such file`）。
**最终改成调 PowerShell**（`Get-NetTCPConnection -State Listen` + `Stop-Process`），一次处理，确定性高：
```bat
powershell -NoProfile -ExecutionPolicy Bypass -Command ^
  "$ports = @(50051,8080,50052,8990,50055,8991,50056);" ^
  "$conns = Get-NetTCPConnection -State Listen | Where-Object { $ports -contains $_.LocalPort };" ^
  "$conns | Select-Object -Unique OwningProcess | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }"
```
回归验证：启动后 7 个监听项 → stop 后 0 个，输出正确列出被结束的 4 个 PID。

批处理文件必须存 **GBK**（含中文标题与注释），否则 chcp 936 下显示乱码。
注意：在 Git Bash 里测试 .bat 时，MSYS 会把 `start` 的 `/D` 等参数当 POSIX 路径改写，
**不能用 `cmd //c 'start ...'` 的方式单独测试 start 命令**，要整体跑 .bat 才准。

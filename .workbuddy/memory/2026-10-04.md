# 2026-10-04 工作日志

## 修复：注册成功后 MySQL 无记录（GateServer /user_register）

### 现象
客户端注册后 MySQL `xxxl.user` 表不增加记录；服务端进程会直接崩溃/卡死（HTTP 请求超时、连接被重置）。

### 根因（三个叠加问题）
1. **表结构与 SQL 不匹配**：`MysqlDao::RegUserTransaction()` 执行
   `INSERT INTO user (uid,name,email,pwd,nick,icon) VALUES (?,?,?,?,?,?)`，
   但实际 `user` 表只有 `id,uid,name,email,pwd` 五列 → MySQL 报
   `ERROR 1054 Unknown column 'nick' in 'field list'` → 抛 SQLException → 回滚 → 返回 -1。
2. **占位符没绑全**：6 个 `?` 只 `setString(1..5)`，`icon` 没绑 → 即使补上列，也会抛
   "Parameter 6 is not set"。
3. **排查难度放大器**：`LogicSystem` 把 `uid==-1`（数据库异常）和 `uid==0`（用户已存在）
   混在一起都回 `UserExist(1005)`，看不到真实原因。

### 修复内容
- `GateServer/MysqlDao.cpp`
  - 补 `pstmt_insert->setString(6, "")`（icon），nick 默认取用户名
  - 借出的连接归还前恢复 `setAutoCommit(true)`，避免污染连接池
  - `RegUserTransaction` / `MySqlPool` 增加 `catch (std::exception&)` 兜底，异常不再打死进程
- `GateServer/const.h`：新增 `DbErr = 1012`（数据库操作失败）
- `GateServer/LogicSystem.cpp`：`uid==-1` → DbErr，`uid==0` → UserExist
- `xxxl.user` 表：
  `ALTER TABLE user ADD COLUMN nick varchar(255) DEFAULT NULL AFTER pwd, ADD COLUMN icon varchar(255) DEFAULT NULL AFTER nick;`

### **关键环境坑（必须记住）**
- **GateServer 必须用 Release 配置运行/调试**：项目引用的
  `D:\Program Files\mysql-connector-c++-26.7.0-winx64` 只提供 **Release 版 DLL**
  （`mysqlcppconn-10-vs14.dll` 导入的是 `MSVCP140.dll`，即 `_ITERATOR_DEBUG_LEVEL=0`），
  而 VS 的 Debug|x64 默认是 `/MDd`（IDL=2）。跨边界传 `sql::SQLString` / `ConnectOptionsMap`
  会因 std::string 布局差 8 字节而读到乱码 → 访问冲突崩溃。
  证据：Debug 下报 `Unable to connect to ??C?:3306`，Release 下正常打印真实错误。
- 已把 `Release|x64` 改为 `Optimization=Disabled` + `DebugInformationFormat=ProgramDatabase`，
  这样 Release 也能正常打断点调试。
- **认证插件目录**：root@localhost 用的是 `mysql_native_password`，连接器 26.7.0 不再内置该插件，
  需要在 exe 同级放 `plugin\` 目录（从 `<连接器>\lib64\plugin` 拷贝）。
  已放到 `GateServer/x64/Release/plugin` 与 `GateServer/x64/Debug/plugin`。
  （也可用连接选项 `pluginDir` 指定。）

## 补充（22:50）：用户切回 Debug 配置仍然崩 → 已把 Debug 配置修好

用户 F5 Debug 配置注册，在 `driver->connect(opts)` 处 `0xC0000005`（读取 0x19）——
就是 /MDd(IDL=2) 与 Release 版连接器 DLL 的 STL 布局不匹配。处理：

1. `GateServer.vcxproj` Debug|x64 改造为 "release 运行时 + 无优化"：
   - `<UseDebugLibraries>false</UseDebugLibraries>`（vcpkg 据此自动改用 Release 库和 Release DLL）
   - ClCompile：`NDEBUG` + `_ITERATOR_DEBUG_LEVEL=0` + `/MD` + `Optimization=Disabled`
     + `DebugInformationFormat=ProgramDatabase` + `BasicRuntimeChecks=Default`
   - Link：库目录改 `installed\x64-windows\lib`，依赖改 `hiredis.lib`，删掉误加的
     `mysqlcppconnx.lib`/`libmariadb.lib`
   - 代价：失去调试 CRT（断言/调试堆），但断点/单步/看变量都正常
2. Debug 目录 DLL 大扫除（关键坑）：vcpkg 的 abseil_dll/cares/libssl-3-x64/re2/jsoncpp
   **Debug 与 Release 文件名完全相同**，目录里残留的 Debug 版会遮蔽。缺 release 的
   `libprotobuf.dll/libprotobuf-lite.dll/z.dll`（applocal 没拷全）+ 残留 debug 版 jsoncpp
   导致进程启动即退（EXIT 127，依赖 MSVCP140D.dll）。全部换成 Release 版，残留的挪进
   `x64/Debug/stale_debug_dlls/`。
3. 验证：Debug 版注册 → HTTP 200 error=0 → `newuser insert into user success`，MySQL 落库 ✓。
   测试数据已清理（user 表恢复 2 行、user_id=3）。

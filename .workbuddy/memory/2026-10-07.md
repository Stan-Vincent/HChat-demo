## GateServer 模块整体梳理（讲解）
用户要求对 `GateServer/` 做细致讲解。通读全部 13 个 .h + 11 个 .cpp（GBK，用 Python 转码读），输出分层、
线程模型、三套连接池横向对比、三条路由的业务逻辑与错误码映射、`/user_register` 跨进程调用链，并列出隐患。

### 关键架构事实（后续改动前必看）
- 线程模型：main 线程 `net::io_context ioc{1}` 跑 acceptor + signal_set；
  `AsioIOServicePool`（size=2，硬编码）跑 async_read/async_write。accept 在主线程，读写在池线程。
- **业务逻辑（MySQL/Redis/gRPC）全部同步阻塞，跑在 io 线程里** → 并发上限 = 池线程数 = 2。
- `GetIOService()` 里 `_nextIOService++` 无锁，目前只有主线程调用所以安全，多线程 acceptor 会 data race。
- `HandlePost` 用 `_request.target()`（含 query string）匹配路由，POST 带 query 参数会 404；
  `HandleGet` 用的是解析后的 `_get_url`。
- `RegGet/RegPost` 用 `std::map::insert` → 同一 URL 注册两次后者静默失效。
- 三套池：RedisConPool(5,hiredis) / MySqlPool(5,JDBC+60s 保活线程) / RPConPool(5,gRPC stub)。
  Redis/MySQL/gRPC 的 `getConnection()` 都是 `cond_.wait` **无超时**，连接耗尽会永久阻塞 io 线程。

### 已识别但尚未修复的隐患
- `RedisMgr` 用 `redisCommand("GET %s", key)` 拼接命令，key/value 含空格会被拆参 → 应改 `redisCommandArgv`
- `AsioIOServicePool::_nextIOService` 无原子/无锁
- `HandlePost` 用 raw target 匹配路由
- `MysqlDao::UpdatePwd` 忽略 `updateCount`（影响 0 行也返回 true）
- `MysqlDao::CheckEmail` 只取第一行，name 无唯一索引
- `user.name` 建议加 UNIQUE 约束，与 `RegUserTransaction` 的查重逻辑对齐
- `VarifyGrpcClient.cpp` 注释写 3 秒超时，代码是 5 秒；类名 `VerifyGrpcClient` 与文件名 `VarifyGrpcClient` 拼法不一致

### 讲解中发现的 bug / 隐患（未修，已告知用户）
1. **`Login` 判断写反**：`if (success) return UidInvalid`，应为 `if (!success)`。
   现状是"token 存在→报 uid 无效；不存在→token_value 空≠token→报 token 无效"，**永远不可能成功**。
2. `getChatServer()` 里负载均衡整段被注释，固定返回 `_servers.begin()->second`；
   若 `_servers` 为空（config.ini 没配 chatserver）解引用 `begin()` 是 UB。
3. `insertToken` 用 `SET` 无 EX → token 永不过期。
4. `~RedisConPool()` 是空的 → 连接从不 redisFree，泄漏；`Close()` 里 `check_thread_.join()`
   重复调用会抛 `std::system_error`。
5. `RedisConPool::getConnection()` 仍是 `cond_.wait` 无超时（GateServer 侧今天已改成 wait_for+3s，
   StatusServer 还没同步）。
6. `ConfigMgr::operator=` **没有 return 语句**（函数返回 `ConfigMgr&` 却无 return）→ UB / C4715。
7. `DistLock` 仍用 `redisCommand("SET %s %s NX EX %d")` 拼接（参数受控，风险低于 GateServer 那次）。
8. `MysqlDao` 用 `driver->connect(url, user, pass)` URL 字符串版（GateServer 已改成 ConnectOptionsMap），
   同为跨 DLL 传 std::string，靠"Debug 配成 release 运行时"规避。

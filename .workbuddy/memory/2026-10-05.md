# 2026-10-05 工作日志

## 修复：Qt 客户端打印的 uid 与 MySQL 不匹配

### 现象
注册成功后 Qt 端 `qDebug() << "user uid is" << jsonObj["uid"].toInt()` 打出来的值对不上库里的 uid。

### 根因
**服务端 `/user_register` 的成功响应里根本没有 `uid` 字段**，只回了 `error / email / user`：

```cpp
root["error"] = 0;
root["email"] = email;
root["user"] = user;      // ← 没有 root["uid"]
```

而客户端 `registerdialog.cpp:160` 读的就是 `jsonObj["uid"]`：字段不存在 → `QJsonValue` 为 undefined →
`toInt()` 返回默认值 **0**。所以无论库里 uid 是多少，客户端永远打印 0。

### 修复
`GateServer/LogicSystem.cpp` 成功分支补一行：
```cpp
root["uid"] = uid;                                  // 客户端读这个字段
std::cout << " register success, uid = " << uid << std::endl;   // 服务端也打一条，便于对照
```

### 验证
Debug 版重编译后跑完整链路：响应 `{"email":..., "error":0, "uid":9, "user":...}`，
MySQL 中该行 `uid=9` —— 完全一致。测试数据（uidcheck）已删除，`user_id` 恢复为 8。

### ⚠️ 另一个容易混淆的点（不是 bug）
`user` 表有两个"号"：
- `id`：自增主键（PK），目前 1,2,9,10,11,12,13 —— 3~8 的空洞是之前调试时插入又删掉的行留下的
- `uid`：业务 id，来自 `user_id` 表（注册时 +1），目前 2~8

**客户端用的是 `uid` 不是 `id`**。在 Navicat 里如果对 `id` 列比对，会看到 id=13 而客户端打印 uid=8，
这是设计使然，不是错误。后续登录/拿用户信息也都走 `uid`。

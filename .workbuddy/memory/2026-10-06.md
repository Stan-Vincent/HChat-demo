### 顺带发现并已修掉的小问题
`RedisMgr::Get` 里 key 不存在时 hiredis 返回 `REDIS_REPLY_NIL`，原代码只判
`!= REDIS_REPLY_STRING`，打出 `failed (not string)`，容易误判成类型错误。已改为先判
`REDIS_REPLY_NIL` → `[ GET xxx ] not found (expired or never requested)`，
真正的类型异常才打 `failed (unexpected reply type: N)`。注册和重置密码两条链路都受益。

## 测试脚本的坑（Git Bash）
1. 变量里带空格的路径（如 `"/d/Program Files/Redis/redis-cli"`）必须用函数包起来，
   直接 `R="..."` 再 `$R SET ...` 会被拆成多个参数。
2. **MSYS 会把 `/reset_pwd` 这类参数当成 Windows 路径转换掉**，传给 Windows 程序时变成
   `C:/Program Files/Git/reset_pwd`，请求路径就错了（服务端返回 url not found）。
   要么用 `MSYS_NO_PATHCONV=1`，要么把路径写在脚本内部拼。
本次做法：改 GBK 文件时用 Python 脚本 `open(p,'rb').read().decode('gbk')` → 改 → `encode('gbk')` 写回，
新注释一律用 ASCII。CRLF 要注意：直接 decode 出来的文本里是 `\r\n`，替换时要写全。

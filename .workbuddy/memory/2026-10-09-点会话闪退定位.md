# 2026-10-09（补充三）：点会话闪退的定位

## 现象（用户第二次补充的关键信息）
- 登录成功 → 通过好友申请 → 界面闪退（第一次报告）
- 进一步确认：**是"点击左侧某个会话条目"时闪退**，不是点"通过"时
- 用户提议：把默认好友删掉回避

## 我的判断：不建议删数据
删掉好友只是回避问题，真实用户加第一个好友就会复现。而点会话这条路径里有两个
**教科书级 Qt 崩溃点**，修起来各只要 1~3 行。

## 点会话的调用链（已逐层读过）
```
ChatDialog::slot_item_clicked(item)
  └─ ui->chat_page->SetChatData(chat_data)          // 有判空保护，安全
       ├─ ui->chat_data_list->removeAllItem();      // ← 嫌疑点 B
       └─ AppendChatMsg(msg)
            ├─ new ChatItemBase(role)
            ├─ new TextBubble(role, msg->GetMsgContent());
            │     └─ 构造里 setPlainText() → initStyleSheet()
            │        ★ 显示时 PaintEvent → eventFilter → adjustTextHeight()  ← 嫌疑点 A
            └─ ui->chat_data_list->appendChatItem(pChatItem)
                 └─ QVBoxLayout::insertWidget(vl->count()-1, item)
```

## 嫌疑点 A（最可能，Qt 官方文档明确标注可空）
`TextBubble::adjustTextHeight()`：
```cpp
for (QTextBlock it = doc->begin(); it != doc->end(); it = it.next())
{
    QTextLayout *pLayout = it.layout();      // ★ 文档未完成布局时返回 nullptr
    QRectF text_rect = pLayout->boundingRect();   // ← 空指针解引用
    text_height += text_rect.height();
}
```
`QTextBlock::layout()` 的 Qt 文档原文：*"Returns the QTextLayout that contains this block,
or nullptr if the block has not been laid out yet."* 代码没判空。
而且它是挂在 **PaintEvent** 上（`eventFilter` 里判断 `QEvent::Paint`）——
**时机恰好就是"点开会话、气泡第一次被绘制"那一刻**，与症状完全吻合。

同一文件还有个次要问题 `setPlainText()`：消息为空时循环不执行，`max_width = 0`，
`setMaximumWidth(0 + margin*2 + ...)` 会让气泡宽度异常小。

## 嫌疑点 B
`ChatView::removeAllItem()` / `appendChatItem()`：
```cpp
QVBoxLayout *layout = qobject_cast<QVBoxLayout*>(m_pScrollArea->widget()->layout());
int count = layout->count();   // ★ 没判 layout 是否为 nullptr
```
`qobject_cast` 类型不符会返回 nullptr。另外这里 `delete widget` 是**立即删除**正在显示的
widget，配合 PaintEvent 期间的重入有风险。

## 另一处未判空
`ChatPage::AppendChatMsg()`：
```cpp
auto self_info = UserMgr::GetInstance()->GetUserInfo();
if (msg->GetSendUid() == self_info->_uid)   // ★ self_info 未判空
```

## 已确认的服务端缺陷（上一轮查的，仍然成立）
`ChatServer::AuthFriendApply` 回包**从不设置 `rtvalue["thread_id"]`**，
客户端 `AuthRsp::_thread_id` 恒为 0 → `ChatThreadData(uid, 0, 0)` →
`_chat_map[0]` + `_chat_thread_items.insert(0, item)`，
与登录时 `loadChatList()` 拉到的真实 thread_id=1 的条目**重复**。

## 结论与建议（已更新：假数据已删）

**用户指出：联系人/新朋友列表里除 xxxl 外全是"自带的"演示数据，本就该删。确认属实并已删除。**

### 假数据生成点（`Client/global.h` 里的三组常量）
```cpp
const std::vector<QString> strs  = {"hello world !", "nice to meet u", "New year，new life", ...};
const std::vector<QString> heads = {":/res/head_1.jpg", ..., ":/res/head_5.jpg"};
const std::vector<QString> names = {"HanMeiMei","Lily","Ben","Androw","Max","Summer","Candy","Hunter"};
```
**关键危害：假数据的 uid 被写死成 0**（`ConUserItem::SetInfo(0, ...)` / `ApplyInfo(0, ...)`），
点它 → `UserMgr::GetFriendById(0)` 查不到 → 返回 nullptr → `ChatUserWid::SetChatData` 里
`other_info->_icon` 空指针解引用 → 闪退。**这就是"点击聊天闪退"的直接原因。**

### 已删除的两处（编译通过，exe 21:53，客户端启动正常）
1. `Client/contactuserlist.cpp` —— `ShowConList()` 末尾 `// 模拟列表` + `for(int i=0;i<13;i++)` 造 13 个假好友
2. `Client/applyfriendpage.cpp` —— `loadApplyList()` 末尾 `// 模拟假数据` + `for(int i=0;i<13;i++)` 造 13 个假申请
   （该 for 循环里还嵌套 `new AuthenFriend` 的 connect，删除时一并去掉了）

`Client/chatdialog.cpp:531` 那处本来就是注释掉的，未动。
删除时注意这两个文件是 **CRLF**，Edit 工具匹配失败，用 Python 正则（`\r?\n`）删的。

### 删除后仍然保留的（**故意的**）
- `applyfriendpage.cpp` 的 `AddNewApply()` / `loadApplyList()` 里给**真实**申请随机分配头像
  （`heads[head_i]`）—— 教程注释写了"以后有头像服务器再改"，属于占位，不是假数据条目。
- `registerdialog.cpp` 注册时随机选头像（`heads[head_i]`）—— 同上。

`strs` / `names` 现在已无实际使用（`chatdialog.cpp` 里那处是注释，`contactuserlist.cpp` 里是
`slot_add_auth_firend` / `slot_auth_rsp` 两个槽里算了却没用的小白变量），保留在 global.h 无害。

### 编译警告确认
`contactuserlist.cpp:199/226 unused variable 'str_i'/'head_i'` 是**既有死代码**
（`slot_add_auth_firend` / `slot_auth_rsp` 里计算了随机值却没用），不是本次删除引起的。

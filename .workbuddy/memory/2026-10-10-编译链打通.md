# 2026-10-10（晚间）：三个服务全部编译通过 + 自建编译验证链

## ★★★ 最重要的事故：protobuf 版本不匹配（3896 个编译错误）

**症状**：ChatServer 编译报 3896 个错，其中大量
`E2614 不能使用 "final" 修饰符声明重载函数`（全在 `message.pb.h` 678~865 行）。

**根因**：
| | 值 |
|---|---|
| `message.pb.h`（protoc **3.x** 生成）检查 | `#if PROTOBUF_VERSION < 3013000` |
| vcpkg 里的 protobuf **6.33.4** 定义的宏 | `GOOGLE_PROTOBUF_VERSION`（在 `runtime_version.h`，**改名了**） |
| 结果 | `PROTOBUF_VERSION` 永远未定义 → MSVC 当 0 → `0 < 3013000` 为真 → `#error` |

**修复**：用 vcpkg 自带的配套工具重新生成
```bash
V=/d/software/vcpkg/vcpkg/installed/x64-windows/tools
"$V/protobuf/protoc.exe" --cpp_out=. -I. message.proto
"$V/protobuf/protoc.exe" --grpc_out=. \
  --plugin=protoc-gen-grpc="$V/grpc/grpc_cpp_plugin.exe" -I. message.proto
```
protoc 33.4 生成的新代码检查 `#if PROTOBUF_VERSION != 6033004`，正好匹配。
⚠️ 重新生成会覆盖 `message.pb.*` / `message.grpc.pb.*`，`.proto` 本身没动。

## cl.exe 抓出的两个我写的真 bug
1. `LogicSystem.cpp`：`rtvalue["thread_id"] = chat_thread_id;` 用在声明之前
   （`AddFriend` 调用在函数后半部分，而 rtvalue 赋值在前）→ `error C2065 未声明的标识符`

   → `error C2819 没有重载成员 operator ->`
两处都是靠 cl.exe 编译才发现的，静态自查（括号配平 / API 名是否存在）查不出来。

## 写服务端代码的教训（本轮血泪）
1. **库大版本升级会静默破坏旧代码**：protobuf 3→6 改了版本宏名，Boost 移除了 `io_context::work`。
   升级 vcpkg 包之后，教程里的 `.pb.cc` 和部分 asio 代码就全废了。
2. **静态自查只能查语法，查不了 API 语义**。括号配平、函数名存在性这些能被 grep 抓出来，
   但「返回值是指针还是值」「变量用在声明前」这类必须有编译器。
3. **所以：任何服务端改动，写完立刻用 cl.exe 编一遍。** 这比让用户编译-报错-我再改的循环快得多。

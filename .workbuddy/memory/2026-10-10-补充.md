## 给数据库用户随机分配头像（已执行）

`user.icon` 原本全是 NULL（uid 2,3）或空串（uid 5~8），导致日志刷
`QPixmap::scaled: Pixmap is a null pixmap`、界面全是空白头像。

**最终执行**（按 uid 轮转，不用纯随机因为 6 个用户里 4 个撞成同一张）：
```sql
UPDATE user
SET icon = CONCAT(':/res/head_', MOD(uid, 5) + 1, '.jpg')
WHERE icon IS NULL OR TRIM(icon) = '' OR icon LIKE ':/res/head_%';
```
结果：uid 2→head_3, 3→head_4, 5→head_1, 6→head_2, 7→head_3, 8→head_4。

**存的是 Qt 资源完整路径**（`:/res/head_3.jpg`），与 `Client/registerdialog.cpp`
注册时 `json_obj["icon"] = heads[head_i]` 的格式一致 —— 这样客户端
`QPixmap(_info->_icon)` 不用改任何代码就能显示。

⚠️ 这个设计本身不理想（DB 里存客户端本地资源路径，服务端用不了、换客户端就失效），
正确做法是只存编号 `head_3`，客户端再拼 `:/res/%1.jpg`。但迁移需要同步改
`registerdialog.cpp` + 3 个渲染点，本次先保持一致，暂不迁移。

## 头像只显示一半的根因：Redis 缓存屏蔽了 MySQL 更新
现象：ChatDialog 里**对方**（xxxl）显示头像，**自己**（test1999）不显示。

**根因：登录回包里两份数据走了不同的读取路径**
| 数据 | 代码路径 | 读源 |
|---|---|---|
| 自己 icon | `LogicSystem::LoginHandler` → `GetBaseInfo("ubaseinfo_<uid>")` | **Redis 优先**，命中旧缓存 `""` |
| 好友 icon | `LoginHandler` → `GetFriendList()` → `MysqlMgr::GetFriendList()` | **直读 MySQL JOIN**，完全绕过 Redis |

所以改了 MySQL 的 `user.icon` 后，对方立刻生效，自己的仍是 Redis 里的旧值。
`GetBaseInfo` 只在「Redis 未命中」时才读 MySQL 并回写缓存，**没有 TTL、没有主动失效**。

**处理**：`redis-cli -p 6380 -a 123456 DEL ubaseinfo_*`（逐个删，管道 DEL 在 Git Bash 下不可靠）。
下次登录会从 MySQL 读新值并重新写入缓存。

⚠️ **Windows 下的坑**：`redis-cli KEYS` 输出带 CRLF，直接 `for K in $(...)` 会把 `\r` 拼进键名导致 DEL 静默失败（返回 0）。必须 `| tr -d '\r'` 再逐行处理。

**根治方案（方案 1 已实施）**：`RedisMgr::Set` 加可选 TTL
```cpp
// RedisMgr.h
bool Set(const std::string &key, const std::string &value, int expire_sec = 0);
// RedisMgr.cpp：expire_sec > 0 时发 SET key value EX <sec>，否则退回原来的 SET key value
```
`const.h` 加 `const int USER_BASE_INFO_TTL_SEC = 3600;`（1 小时）。

**关键坑：ChatServer 里有 5 处独立的"读 MySQL 后回写缓存"逻辑**，
只改一处会被其它处覆盖回永久缓存。全部已加 TTL：
| 文件 | 函数 | 键 |
|---|---|---|
| LogicSystem.cpp | `GetBaseInfo` | `ubaseinfo_<uid>` |
| LogicSystem.cpp | `GetUserByUid` | `ubaseinfo_<uid>` |
| LogicSystem.cpp | `GetUserByName` | `nameinfo_<name>` |
| ChatServiceImpl.cpp | `GetBaseInfo` | `ubaseinfo_<fromuid>` |
| ChatGrpcClient.cpp | `GetBaseInfo` | 调用方传入 |

另两处 `Set()` 保持 2 参（默认参数兜底）：`Set(ipkey, server_name)`（uip_）、`Set(uid_session_key, ...)`（usession_）。
⚠️ `usession_` / `utoken_` **故意不给 TTL** —— token 靠 TTL 会失效踢人；usession_ 要活到断线清理。

**教训**：加缓存过期时，必须 `grep` 出所有写同一类键的地方，别只改你看到的那一处。
另：Windows Python 读 .py 脚本时若脚本含中文注释，可能与内联执行结果不一致 ——
批量改 GBK 文件时优先用 `bash << 'PYEOF'` heredoc（已验证可靠），比写临时 .py 文件稳。

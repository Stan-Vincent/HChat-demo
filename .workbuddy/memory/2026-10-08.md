### 架构要点
- `TcpMgr` 与 `HttpMgr` 是**并列的两套网络层**，类模板一致（`QObject + Singleton<T> + enable_shared_from_this<T>`，
  构造函数里 `connect(this, &X::sig_send_data, this, &X::slot_send_data)` 自连自发）。
- **登录是两段式**：
  ① HTTP `POST /user_login` → GateServer（内部 gRPC 调 StatusServer 拿 ChatServer 的 host/port）
  → 回 `{uid, host, port, token}` → ② `emit sig_connect_tcp(ServerInfo)` → TcpMgr 连 ChatServer
  → 发 `ID_CHAT_LOGIN` → 回 `ID_CHAT_LOGIN_RSP` → `sig_swich_chatdlg`
- **帧协议**：`quint16 id (BigEndian) + quint16 len (BigEndian) + JSON body`，len 是 quint16 → 单包上限 65535。
- **半包/粘包处理**（接收端核心）：`_buffer += readAll()` → 够 4 字节头就 `stream >> _message_id >> _message_len`
  并 `_buffer.mid(4)` 消费 → body 不够则 `_b_recv_pending = true` 并 return → 够则 `mid(0,len)` 取出、
  `handleMsg()`、**`forever` 循环继续拆下一个包**。
  `_message_id/_message_len` 必须是成员而非局部（半包要跨下次 readyRead 记住）。
  `_buffer = _buffer.mid(n)` 赋值后 QByteArray 设备读位置归零，所以每次重建 `QDataStream stream(&_buffer, ReadOnly)` 从 0 读是对的。
  接收端没调 `setByteOrder`，但 QDataStream 默认就是 BigEndian，和发送端一致。
- `handleMsg` 用 `_handlers.find(id)` + 先判 `end()`，比 HttpMgr 侧的写法规范。
- `_handlers` 只注册 5 个 ReqId，其中**只有 `ID_CHAT_LOGIN_RSP` 真正生效**（其余处理体被注释，
  依赖还没写的 `UserMgr`：`UserInfo` / `SearchInfo` / `AddFriendApply` 等）。

## 重要环境坑：命令行编译 Client 不能用 MSYS2 的 g++
- 现象：用 `C:\msys64\mingw64\bin` 的 GCC 16.1 增量编译后，链接报
  `undefined reference to __emutls_v._ZSt11__once_call`（在 registerdialog.o 上）。
- 根因：**Qt Creator 用的是 Qt 自带的 MinGW 11.2.0**（`D:\QT6\Tools\mingw1120_64`），
  我用 MSYS2 GCC 16.1 编出来的 `.o` 混进同一个构建目录 → 两套 libstdc++ 的 emutls 符号对不上。
  注意 MSYS2 的 `libstdc++` 里 `__emutls_v._ZSt11__once_call` 出现 0 次，Qt 两个 MinGW 都有。
- **Qt Creator 的 kit id 有误导性**：`qt.qt6.653.win64_mingw_kit` 绑定
  `qt.tools.win64_mingw900.g++`（名字像 9.0），但 `toolchains.xml` 里它的
  `DisplayName` 是 **"MinGW 11.2.0 64-bit for C++"**，实际指向 `D:\QT6\Tools\mingw1120_64`。
  查证路径：`%APPDATA%\QtProject\qtcreator\profiles.xml`（kit→ToolChain）
  + `toolchains.xml`（ToolChain Id→DisplayName/路径）。
- **正确做法**：命令行编译 Client 用
  `export PATH=/d/QT6/Tools/mingw1120_64/bin:$PATH` 后再 `mingw32-make`；
  若之前用别的工具链编过，先 `mingw32-make clean` 再全量重编。
- GateServer/StatusServer 用 MSVC，不受此影响。
- 处理结果：删掉 `build/Desktop_Qt_6_5_3_MinGW_64_bit-Debug/debug/*.o`（`mingw32-make clean` 删不干净，
  会残留 MSYS2 编的 logindialog.o），再用 MinGW 11.2 全量重编 → `bin/Hchat.exe` 链接成功（16.6 MB）。
  `copy /Y` 报 Error 127 依旧是老问题（cmd 内建命令，bash 下没有），不影响 exe。

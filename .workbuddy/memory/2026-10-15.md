## 登录后立即闪退（已修复并验证，16:55）
### 现象
登录成功 1~2 秒进程消失，`bin/crash.log` 连着 6 条 `===== crash (signal 11) =====`，
自带 handler 只能打 `<no symbol>`，看不出是哪个函数。

### 定位手段（可复用）
1. **gdb 抓符号化栈**：Qt 自带 MinGW 带 gdb，`D:\QT6\Tools\mingw1120_64\bin\gdb.exe`。
   - **在 Git Bash 里传 `-ex "set confirm off"` 会被拆词**（报 `Excess command line arguments
     ignored` / `confirm: No such file or directory`）→ 改成把命令写进 gdbcmd.txt 用 `-x` 传，
     并用 Windows 终端工具调用；输出重定向到文件再读。
   - 脚本：`set confirm off` / `set pagination off` / `run` / `bt 40` / `quit`。
2. **让崩溃自动复现**：把 `bin/login.ini` 的 `auto_login=false` 临时改 `true`（密码是 DPAPI
   密文，能自动登录），gdb 不用人工点登录就能跑到崩溃点。**用完必须改回 false。**
3. 判断是否还崩：以 `crash.log` 有无新增条目为准（最硬），辅以存活 20s 以上。
   注意后台起的 exe 会在 bash 命令结束/沙箱清理时被杀，不能单凭"进程没了"判定崩溃。

### 根因：成员先使用后初始化
`ChatUserWid` 构造函数第 19 行 `ShowRedPoint(false);`，而 `_unread_lb = new QLabel(this)`
在第 23 行。上一批把 `ShowRedPoint()` 重写成 true→`addUnread(1)` / false→`clearUnread()`，
`clearUnread()` 里 `_unread_lb->hide()`；`_unread_lb` 头里初值 `nullptr` → 对 nullptr 调
`QWidget::hide()` 段错误。登录加载会话列表 `ChatDialog::slot_load_chat_thread`
（chatdialog.cpp:414）new 第一个 ChatUserWid 就必崩。
栈：`QWidget::hide()` ← `clearUnread`(chatuserwid.cpp:133) ← `ShowRedPoint`(:146)
    ← `ChatUserWid::ChatUserWid`(:19) ← `slot_load_chat_thread`(chatdialog.cpp:414)

### 修复（Client/chatuserwid.cpp）
- 构造顺序：先 `new QLabel` + `hide()`，再 `ui->red_point->raise(); ShowRedPoint(false);`，
  注释写明"顺序反了必崩"。
- `clearUnread()`：加 `if (_unread_lb)` 判空，并补 `AnimUtil::stopRedDotPulse(ui->red_point)`
  + `ui->red_point->hide()`（原来只收数字徽标，旧红点没收 → 两个标同时出现）。
- `addUnread(int n)`：`if (n <= 0 || _unread_lb == nullptr) return;` 兜底。

### 验证
Qt MinGW `mingw32-make -j4` 重编（尾部 `Makefile.Debug:388 Error 127` 是 bash 下 `copy`
内建命令的已知无害报错，链接其实成功）→ 自动登录跑 25s 存活、`crash.log` 无新增 →
已杀进程、恢复 `auto_login=false`、删掉 gdbcmd.txt/gdbout.txt/login.ini.bak。

### 教训（写进长期备忘的候选）
改写"兼容包装函数"（ShowRedPoint）时，若它被子控件构造函数调用，必须检查它现在间接摸了
哪些**运行时才创建**的成员——原实现只摸 `ui->`（setupUi 后已存在），新实现摸了后建的裸指针。

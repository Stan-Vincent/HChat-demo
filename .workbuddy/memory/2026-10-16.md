## 断线自动重连 + 网络状态提示条（21:22~22:00，已实测两条路径）

### 实现
- **TcpMgr（tcpmgr.h/cpp）**：重连状态机。`StartReconnect/StopReconnect/IsReconnecting/IsConnected`；
  成员 `_last_server_info`（首次连接的 host/port 原样留着，重连复用）、`_reconnect_timer`（退避）、
  `_connect_watchdog`（单次 connect 4s 看门狗，防 Connecting 卡死）。
  退避 1s/2s/4s/8s/8s，最多 `kMaxReconnectAttempts=5` 次。
  信号：`sig_reconnect_retry(attempt,total)` / `sig_recon_success()` / `sig_reconnect_failed()`。
  - 重连的 socket connected 后**自己重放 CHAT_LOGIN**（uid+token），不发 `sig_con_success`
    （那是登录页流程用的，会误导 LoginDialog）。
  - 重连时的 login rsp：`UserMgr::Clear()` 后重灌（AppendFriendList/AppendApplyList 是追加语义，
    不清会翻倍；token 要留着），成功后发 `sig_recon_success` 而**不是** `sig_swich_chatdlg`
    （否则 MainWindow 重放登录淡入淡出 + 重复 loadChatList）。
  - 重连中任何 socket error 都不再发 `sig_con_success(false)`，只走退避。
  - `CloseConnection()` 里 `StopReconnect()`（主动登出要取消重连，否则旧账号被自动拉回）。
  - disconnected 里清 `_buffer`/`_b_recv_pending`（半开连接的残包会让重连后解包错位）。
- **NetStatusBanner（定义在 mainwindow.cpp 里，避免改 .pro / 重跑 qmake）**：常驻顶部细条，
  滑入/更新文案/滑出，`WA_TransparentForMouseEvents` 不挡交互；重连期间反复更新"正在重连(n/5)"。
  用常驻条而不是 Toast：重连要持续几十秒，Toast 会自动消失。
- **MainWindow**：`slot_connection_closed` 改为——`IsReconnecting()` 为真就挂横幅等结果，
  为假（登录页阶段断开、手里没 token）才走原来的 Toast + offlineLogin。
  新增 `slot_reconnect_retry/slot_recon_success/slot_reconnect_failed`；
  `resizeEvent` 里 `reposition()`，`offlineLogin()` 里 `dismiss()`。
- **ChatDialog::refreshAfterReconnect()**：清会话列表行 + `_chat_thread_items` + `_cur_chat_thread_id`
  + `chat_page->resetForLogout()` 后 `loadChatList()`（`slot_load_chat_thread` 只追加不清空，不清会出现两行）。
- **ChatPage::on_send_btn_clicked**：开头加 `TcpMgr::IsConnected()` 检查，断线时 Toast 提示
  （否则 write 静默成功、气泡显示已发送但对端永远收不到）。
- **新增 `UserMgr::GetToken()`**。

### 实测踩到并修掉的 3 个 bug（都是"看起来对、跑起来错"的典型）
1. **token 来源搞错**：原来 `UserMgr::SetToken(jsonObj["token"])` 读的是 **CHAT_LOGIN_RSP** 的
   token 字段，而 ChatServer **根本不下发**这个字段（token 是 GateServer HTTP 登录回包给的，
   LoginDialog 只存在自己 `_token` 成员里）→ `UserMgr::_token` 永远是空串 →
   "是否登录过"判断永远失败、重连永远不启动。
   修：LoginDialog 收到 HTTP 回包时 `UserMgr::SetToken(si.Token)`；tcpmgr 侧改为"回包带了才覆盖"。
2. **emit 顺序反了**：disconnected 里先 `emit sig_connection_closed()` 再 `StartReconnect()`。
   emit 是**同步**调用，MainWindow 槽函数里查 `IsReconnecting()` 时重连还没起 →
   每次都走回登录页分支。修：先 StartReconnect() 再 emit。
3. **心跳定时器 nullptr（既有严重 bug，不止影响重连）**：`chatdialog.cpp` 构造里的 `_timer`
   （10s 一跳）直接 `user_info->_uid`，而 `offlineLogin()` 的 `UserMgr::Clear()` 会把 `_user_info`
   置空，ChatDialog 却是常驻对象、定时器不停 → **任何一次退出登录/断线回登录页，10 秒内必崩**。
   gdb 断在 `QCoreApplication::quit` 抓到的栈顶就是 `chatdialog.cpp:174`。
   修：lambda 里判空 + `clearSessionState()` 停表 + `applyLoginSession()` 重启表。

### 验证（test/test_reconnect_e2e.sh + test/test_reconnect_fail.sh）
- **成功路径**：kill ChatServer → 3s 后重启 → 客户端
  `StartReconnect → attempt 1 → Connected → redo chat login handshake → reconnect login ok
  → sig_recon_success → refreshAfterReconnect`，全程**没有回登录页**，客户端存活、crash.log 无新增。

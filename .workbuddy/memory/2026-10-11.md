### Bug1：提交按钮被连接了两次（双击触发）
- 根因：`userinfopage.cpp` 里 `submit_btn` 的 objectName 就是 `submit_btn`，且
  `on_submit_btn_clicked` 是 `private slots` → `setupUi` 已自动 connect 一次；

### Bug2a：主动登出被当成心跳超时
- 根因：`ChatDialog::slot_logout` 先 `TcpMgr->CloseConnection()` 关 socket，触发
  `disconnected`→`emit sig_connection_closed()`→`MainWindow::slot_connection_closed`
  弹"心跳超时或临界异常，该终端下线！"。这是给"服务端真掐连接"用的，主动退出不该弹。
- 修：`tcpmgr.h/.cpp` 加 `bool _b_intentional_close`。`CloseConnection()` 置 true 再关；
  `disconnected` 信号仅在 `!_b_intentional_close` 时转发 `sig_connection_closed`；
  `slot_tcp_connect` 开头复位 false（保证新连接被服务端掐掉仍能弹）。
  现在主动退出/被踢走各自逻辑，不再误弹心跳框。

### Bug2b：登出后登录页卡死
- 根因：登录成功后 `LoginDialog` 按钮被 `enableBtn(false)` 禁用、提示停在
  "聊天服务连接成功，正在登录..."；切回登录页时这个 UI 状态没复位 → 界面"无法使用"。
  （用户口述的"正在跳转登录"就是这条提示。）
- 修：`logindialog.cpp` 新增 `LoginDialog::resetUIState()`（恢复按钮 + 清提示）；
  `MainWindow::offlineLogin()` 在 `if(_ui_status==LOGIN_UI) return;` 守卫【之前】调用它，
  保证心跳超时那条路径先切了 LOGIN_UI 也不漏复位。

### "没保存"真相：Redis 缓存没失效（服务端缓存一致性，不是客户端 bug）
- 根因（关键！）：`GateServer::/update_userinfo` 只 `UPDATE user ...` 写 **MySQL**；

## 修复：重启程序后头像变空白（10:6x）

用户最后报告：同进程内 退出登录→登录 头像能看到（上传保存了），但**重启程序后头像变空白**。

### 根因
用户的**自己头像**从来没走 HTTP 下载，两处都直接 `QPixmap(icon_url)` —— 把服务端返回的
URL（如 `"upload/xxx.png"`）当成**本地文件路径**去读，必然失败 → 空白。
- `chatdialog.cpp:80-84`（`side_head_lb` 左侧栏头像）：`QPixmap pixmap(head_icon);`
- `userinfopage.cpp:36`（`head_lb` 资料页头像）：`QPixmap pixmap(info->_icon);`
而真正能下载的 `ImageManager::downloadImage` 只在 `chatpage.cpp:82` 用于**聊天消息图片气泡**，
对自己头像从未调用。
所以：
- 同进程内"能看到"只是因为 `on_up_btn_clicked` 选完图就 `refreshHeadPreview(cropped)` 把
  **内存里的裁剪预览**设上了（不是下载的），一重启就没了。
- 重启后构造页走 `QPixmap(url)` → 失败 → 空白。

### 修
两处都改成异步 `ImageManager::instance()->downloadImage(icon, cb)`，回调里把 pixmap 设到 label；
回调用 `QPointer<...> guard(this)` 兜底（下载途中退出登录销毁页面时不会 use-after-free）。
- `userinfopage.cpp`：构造里 `downloadImage(info->_icon, ...)` → `guard->refreshHeadPreview(pix)`；
  加 `#include "imagemanager.h"` + `#include <QPointer>`。
- `chatdialog.cpp`：`side_head_lb` 同样改 `downloadImage(head_icon, ...)`；加同样的 include。
`refreshHeadPreview` 是 `userinfopage.h` 的 private 方法，但 lambda 定义在成员函数作用域内，
能访问 private 成员（访问控制在词法作用域判定），编译通过。
